# Project Memory

See @README for the repository overview.

For broad orientation in the note layer, start with @Notes/Index.md.

## Core Expectations

- The vault's files are the source of truth.
- `Inbox/` is for human intake, not generic agent staging.
- Durable knowledge belongs in `Notes/`.
- Canonical paper PDFs belong in `Library/Papers/`.
- Prefer links, local metadata, index notes, and overview notes before adding folder taxonomy.
- Prefer Obsidian-aware operations when note identity or paths matter.
- Keep edits bounded, reviewable, and reversible.

## Content Index

`Notes/Index.md` is the curated entry point into the note layer.

- Read it early for broad or exploratory note work.
- Use it as a starting surface, not as a complete map.
- Update it only when navigation materially improves.

## Completion Evidence

For skill-shaped tasks, include brief evidence in the final response:

- broad questions: whether the index was consulted, main note anchors, and whether PDFs were needed
- ingestion tasks: final destinations, duplicate outcome when relevant, and whether the index changed
- maintenance passes: scope, durable artifacts added or refreshed, and whether the index changed
- path-sensitive edits: whether Obsidian-aware operations were used, or why a direct edit was safe
